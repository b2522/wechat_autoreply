# 微信群消息自动回复机器人 · 使用说明

> 基于「截图 + OCR + 键鼠自动化」的微信 PC 端群消息自动回复工具，专治微信 4.x（Qt 自绘界面）读不到消息文本的场景。

---

## 一、它能做什么

在指定微信群里，当有人发出**包含特定关键词**的消息时，机器人会自动在群里回复一条固定内容，例如：

- 群内出现「关键词」
- 机器人延迟一段时间后，自动在群里发出「回复消息」

并且带防刷屏：限定时间内全局只发一条。

---

## 二、工作原理

微信 4.x 用 Qt 自绘界面，消息列表不暴露给标准的 UI 自动化接口（传统 `uiautomation` 读不到文字）。所以本工具走 **RPA 标准打法**：

```
每 5 秒（poll_interval）
  └─ 截取聊天区域（PrintWindow，后台也能截到真实内容，不抢焦点）
       └─ OCR 识别区域内文字（RapidOCR）
            └─ 与上一次扫描做差分，只取"本轮新出现"的消息
                 └─ 任意一条含关键词 → 进入"待发送"计划
                      └─ 随机延迟 30~60 秒后，自动键鼠发送「回复消息」
                           └─ 5 分钟内全局最多只发 1 条
```

**关键设计点：**

- **后台可捕捉**：截图用 `PrintWindow`（带 `PW_RENDERFULLCONTENT`），即便群窗口在后台、被遮挡也能拿到真实内容，**不需要窗口处于前台**。旧方案用 `ImageGrab`(BitBlt) 才需要前台，已废弃。
- **差分防漏防重**：用「上一次扫描可见消息集合」做差分，只有本轮新出现的消息才当候选。同一句话被不同人反复发也能每次触发（只受 5 分钟限流约束），而历史消息不会刷屏。
- **健壮性自愈**：
  - 窗口被最小化 → 自动恢复（不抢焦点）
  - 连续 3 次 OCR 为空（窗口未渲染）→ 自动重定位窗口
  - 每 60 秒自动滚到底部（确保新消息在可视区；抢焦点约 0.5 秒后归还你原先使用的窗口）

## 五、配置说明（config.json）

修改 `config.json` 后**重启脚本**生效。不要去改 `wechat_autoreply.py` 里的 `DEFAULT_CONFIG`——它只是「首次运行自动生成 config.json 的模板」，日常调参只认 `config.json`。

```json
{
  "group_name": "测试群",
  "keywords": ["刘德华收到", "张学友收到"],
  "reply": "收到",
  "poll_interval": 3,
  "reply_delay_min": 10,
  "reply_delay_max": 60,
  "reply_interval_minutes": 1,
  "scroll_to_bottom_interval": 60,
  "max_empty_ocr_recover": 3,
  "manual_open_only": true,
  "verbose": true
}
```

| 字段 | 当前值 | 含义 | 调优建议 |
|------|--------|------|----------|
| `group_name` | — | 监听的群名（需与微信**窗口标题**一致，含此串即可） | 改名后窗口标题不变也能定位 |
| `keywords` | — | 触发关键词列表，消息**包含任一**即触发 | 按需增删，支持短语 |
| `reply` | — | 自动回复内容 | 固定文本 |
| `poll_interval` | 3 | **扫描间隔（秒）**。每隔几秒截图+OCR 一次 | 调小→响应更快但更费资源；调大→更省 |
| `reply_delay_min` / `reply_delay_max` | 10 / 60 | 检测到关键词后，**随机延迟**这个范围（秒）再发送，更像人工 | 想更慢就调大 |
| `reply_interval_minutes` | 1 | **全局限流**：该分钟数内最多只发 1 条回复 | 调大=更宽松；调小=更克制 |
| `scroll_to_bottom_interval` | 60 | 每隔多少秒把聊天**滚到底部**（确保新消息在可视区）。`0` = 关闭自动滚动 | **设为 0 可做到零焦点干扰、完全后台运行**（代价：你若手动上翻，新消息可能暂时截不到） |
| `max_empty_ocr_recover` | 3 | 连续多少次 OCR 为空就重定位窗口（自愈） | 一般不需要改 |
| `manual_open_only` | true | `true`=脚本**不搜索、不打开群**，只使用你手动打开并固定在最前的窗口；`false`=找不到时自动 Ctrl+F 搜索打开 | 按你要求已设为 true |
| `verbose` | true | `true`=每轮扫描输出当前可见关键词数量，便于排查 | 调试用，稳定后可改 false |

## 七、首次运行会发生什么

当前配置 `manual_open_only: true`，所以：

1. **你自己手动在微信里打开目标群聊窗口**，并保持在屏幕可见（可固定在最前）。
2. 运行脚本。脚本会直接定位这个已打开的窗口；**不会帮你搜索/打开群**。如果找不到窗口，会提示你手动打开后重跑。
3. **首次扫描只建立基线**：把当前可见消息记下来，不触发回复，避免对历史消息刷屏。
4. 之后每轮只处理「新出现」的消息。

## 八、常见现象与排查

**Q1：是不是必须让微信群窗口保持在前台？**
不需要。当前方案用 `PrintWindow` 后台截图，窗口在后台/被遮挡也能捕捉。唯一会短暂碰焦点的是每 60 秒的「滚到底部」（约 0.5 秒后归还你原来的窗口）。若想完全零干扰，把 `scroll_to_bottom_interval` 设为 `0`。

**Q2：群里明明有关键词，为什么不自动回复？**

本机器人只回复**脚本启动后新出现**的关键词消息；启动前已经在窗口里的关键词会被当作基线，不会触发。这是为了避免一启动就对历史消息刷屏。

如果你确认有人**在脚本运行后**新发了关键词但仍未回复，请按下面顺序排查：
1. 看 `wechat_autoreply.log` 里的 `[verbose]` 行，确认当前扫描是否识别到了关键词。
2. 确认 `manual_open_only: true` 时，你**已经手动打开**了目标群窗口，且窗口没有被最小化。
3. 确认没有把群**手动往上翻**且关闭了自动滚动——那样新消息在可视区下方，截不到。
4. 若连续出现 `[警告] 聊天区域持续不可读` 或 `[重定位窗口]`，说明窗口状态异常，脚本在自愈。

**Q3：同样的「广电已封堵」被不同人反复发，只回一次？**
不会。差分逻辑让重复短语每次都当新消息触发，只受 `reply_interval_minutes`（默认 5 分钟）全局限流约束。

**Q4：机器人会回复自己的消息导致死循环？**
不会。`reply` 内容（「回复消息」）不含关键词，双保险规避死循环。

## 九、注意事项与风险提示

- **本工具依赖屏幕截图与模拟键鼠，属于个人微信自动化灰区方案**。微信官方无开放 API，存在一定封号/版本适配风险（微信更新可能需重新调试截图区域）。
- 建议先在**测试群 / 私聊窗口**跑通再上真实工作群。
- 自动发送功能请在确认无误后再启用；本仓库的代码层面已尽量防刷屏、防死循环，但仍请保持关注日志。
- **请勿用于骚扰、广告或违反群规的场景**，责任自负。
